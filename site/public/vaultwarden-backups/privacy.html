Vaultwarden Backups: privacy and Google data use

Updated 5 November 2026. Operator and contact: Ny Hasinavalona Randriantsarafara, nyhasinavalonar@gmail.com.

Purpose and access

The operator connects their own Google account to store and recover encrypted backups of a private Vaultwarden instance. The application requests the Google Drive drive.file scope, which allows access to files created or opened with this application. It reads backup-file metadata and encrypted backup contents, writes new backups, checks them and removes expired backup objects. It may read aggregate storage-quota information to check capacity.

The application does not request access to Gmail, Contacts or unrelated Drive files. It has no public signup. A family member's vault account does not authorize access to that member's Google account.

Storage and sharing

Restic encrypts backup contents on the operator's server before upload to Google Drive. Google receives encrypted backup objects and their file metadata, not the backup decryption password or a plaintext credential export.

OAuth credentials are stored in private configuration on the operator's server and recovery computer. The VPS is hosted by OVHcloud. Resend provides account and backup-failure emails; backup-failure messages contain no vault contents or credential values. Google data is used only to provide this backup and recovery function. It is not sold, used for advertising or used to train AI models.

Retention and controls

The configured backup history is 30 days. Restic removes expired objects only within this backup repository; it does not empty the account's Drive trash. Temporary local backup copies are removed after each attempt.

The operator can revoke the application's access in their Google account connections. Revocation stops access but does not itself delete existing encrypted backups. The operator can delete those files in Google Drive and remove the local OAuth configuration. Contact the operator for questions about backup retention.
